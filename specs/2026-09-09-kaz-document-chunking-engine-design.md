# Kaz-DocumentEngine: Multi-Paragraph Sliding Window Chunking & Aggregation Specification

**Date:** 2026-09-09  
**Status:** Approved  
**Topic:** Step 2 — Document-Level Inference & Hybrid Text Detection  
**Target System:** `kazakh-ai-text-detection`

---

## 1. Executive Summary & Problem Statement

The dual-stream `MorphoContrastiveDetector` achieves state-of-the-art detection on paragraph-level Kazakh texts ($0.9980$ ROC-AUC on formal news/Wikipedia, $1.0000$ on unseen wild generators). However, the model has a fixed sequence capacity of $256$ tokens (~$180\text{--}220$ words).

In practical deployments (e.g., student essays, news articles, academic theses, legal documents), documents range from $500$ to $10{,}000+$ words and frequently contain **hybrid compositions** (e.g., an authentic human document containing 1 or 2 paragraphs generated by an LLM). 

A single-pass truncation approach:
1. Misses any AI text occurring past token 256.
2. Cannot localize which specific sections or paragraphs were machine-generated.
3. Fails to provide fractional composition metrics (e.g., "35% of this essay was generated by AI").

This specification defines **Step 2**: a sentence-preserving sliding window chunker and intelligent Top-$K$ worst-chunk aggregator capable of analyzing arbitrary-length Kazakh documents with localized explainability.

│   - Semantic stream: KazRoBERTa subword embeddings                     │
│   - Morphological stream: FST morpheme sequence encoding               │
│   - Dynamic Gate: Computes g per chunk                                 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                DocumentAggregator & Calibrator                         │
│                                                                        │
│   - Top-K Worst-Chunk Pooling: captures localized AI insertions        │
│   - Calibrated probability scaling (using optimal threshold tau*)      │

│   - Character-level spans for highlight visualization                  │
└────────────────────────────────────────────────────────────────────────┘

### 2.1 Component Definitions

1. **`DocumentChunk`** (`kaz_mage/document.py`):
   Data container representing a single window:
   - `index: int`: Zero-based chunk order.
   - `text: str`: Text content of the chunk.
   - `start_char: int`: Starting character offset in the source document.
   - `end_char: int`: Ending character offset in the source document.
   - `word_count: int`: Number of whitespace-delimited words.
   - `sentence_count: int`: Number of sentences enclosed.
   - `ai_probability: float`: Predicted probability of AI generation $[0.0, 1.0]$.
   - `gate_value: float`: Mean dynamic fusion gate weight $\mathbf{g} \in [0.0, 1.0]$.

2. **`SentencePreservingChunker`** (`kaz_mage/chunker.py`):
   Linguistic segmentation engine:
   - Splits document into paragraphs along `\n+`.
   - Splits paragraphs into sentences using regex boundary matching while preserving Kazakh abbreviations:
     - `т.б.` (*тағы басқалар*)
     - `ж.б.` (*және басқалар*)
     - `ғ.` (*ғасыр*)
     - `ж.` (*жыл*)
     - `қ.` (*қала*)
     - `мыс.` (*мысалы*)
     - `проф.` (*профессор*), `акад.` (*академик*)
   - Groups sentences into chunks up to `max_words` (default: 200 words, hard max: 220 words).
   - Slides forward with `overlap_sentences` (default: 1 sentence overlap between consecutive chunks).
   - Guarantees: **Zero severed words or agglutinative suffixes**.

3. **`DocumentAggregator`** (`kaz_mage/aggregator.py`):
   Aggregation and calibration logic:
   - Computes Top-$K$ worst-chunk probability.
   - Computes volume-weighted AI content ratio.
   - Maps scores to the three-tier categorical verdict.

4. **`DocumentDetector`** (`models/document_detector.py`):
   High-level facade class wrapping `MorphoContrastiveDetector`:
   - `predict_document(text: str, top_k: int = 2) -> DocumentAnalysisResult`
   - Handles batching to ensure $M$ chunks are evaluated in a single GPU/CPU forward pass.

## 3. Mathematical Formulation

### 3.1 Top-$K$ Worst-Chunk Aggregation
Let document $D$ be partitioned into $M$ chunks $\{C_1, C_2, \dots, C_M\}$ with predicted AI probabilities $\{p_1, p_2, \dots, p_M\}$.

Sort the chunk probabilities in descending order:
$$p_{(1)} \ge p_{(2)} \ge \dots \ge p_{(M)}$$

The number of evaluated worst chunks $K$ is dynamically scaled:
$$K = \max\left(1, \min\left(k_{\text{cfg}}, \lceil 0.25 \times M \rceil\right)\right)$$
*(Default $k_{\text{cfg}} = 2$)*.

The document peak risk score is:
$$p_{\text{worst}} = \frac{1}{K} \sum_{i=1}^{K} p_{(i)}$$

### 3.2 Volume-Weighted AI Ratio
To quantify the extent of machine generation throughout the document:
$$\text{Ratio}_{\text{AI}} = \frac{\sum_{i=1}^{M} \mathbb{I}(p_i \ge \tau^*) \cdot \text{WordCount}(C_i)}{\sum_{i=1}^{M} \text{WordCount}(C_i)}$$
where $\tau^*$ is the calibrated optimal decision threshold (empirically derived as $\tau^* = 0.998$ for the contrastive model).

### 3.3 Three-Tier Categorical Verdict
$$\text{Verdict} = 
\begin{cases} 
\text{"Authentic Human"}, & \text{if } p_{\text{worst}} < \tau^* \\ 
\text{"Partially AI / Hybrid"}, & \text{if } p_{\text{worst}} \ge \tau^* \text{ and } \text{Ratio}_{\text{AI}} < 0.70 \\ 
\text{"Machine-Generated"}, & \text{if } \text{Ratio}_{\text{AI}} \ge 0.70 
\end{cases}$$

## 5. Verification & Testing Plan

### 5.1 Unit Testing
1. **`tests/test_document_chunker.py`**:
   - `test_kazakh_abbreviations`: Confirms abbreviations (*т.б.*, *ж.б.*, *ғ.*, etc.) are never split into separate sentences.
   - `test_sentence_preserving_packing`: Confirms every chunk contains only intact sentences up to 220 words.
   - `test_sliding_overlap`: Asserts adjacent chunks overlap by exactly the configured sentence count.
   - `test_character_offset_fidelity`: Verifies `document[c.start_char : c.end_char]` matches `c.text` without drift.
   - `test_edge_cases`: Handles empty text, 1-word inputs, single sentence $> 250$ words, and malformed whitespace.

2. **`tests/test_document_aggregator.py`**:
   - `test_top_k_worst_chunk_calculation`: Tests mathematical correctness across varying chunk counts ($M=1, M=3, M=10$).
   - `test_three_tier_verdicts`: Verifies transitions between `"Authentic Human"`, `"Partially AI / Hybrid"`, and `"Machine-Generated"`.
   - `test_calibration_threshold_scaling`: Asserts proper behavior around threshold $\tau^*$.

3. **`tests/test_document_detector.py`**:
   - `test_predict_document_integration`: End-to-end forward pass with batched evaluation.
   - `test_mixed_document_detection`: Synthesizes a hybrid document (3 human paragraphs + 1 Sherkala/Qwen paragraph) and asserts that the injected AI paragraph is flagged while the overall verdict correctly returns `"Partially AI / Hybrid"`.

### 5.2 Global Constraints
- `aist2026/paper.tex` strictly untouched under all circumstances.
- All 102 existing regression tests must pass cleanly.
